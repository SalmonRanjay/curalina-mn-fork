## Objective

Convert a `quizResponses` row into recommendation's `DesignProfileIn` shape
and call recommendation's `/v1/recommendations` (and, where the flag is on
and a bundle is requested, `/v1/bundles`) over HTTP; map recommendation's
response (`BundleLineItem`/candidate product references) back onto the
app's own `products` rows for display. This is the first two rows of
`ui_adapter_workflow.md`'s required-mappings table plus deliverable 2, and
deliverable 5 scoped to this leg only. Depends on `UI-A5-01` (flag/settings
module) being merged first.

**A real gap you must not paper over.** Recommendation's `Product` domain
class (`ai_services/recommendation/src/curalina_recommendation/domain/product.py`
lines 1–9) **deliberately does not have an `asset_refs` field yet** — its
own docstring says it was "omitted rather than speculatively stubbed" and
recommendation has no per-product or per-asset HTTP endpoint (only whole-
catalogue import via `/v1/catalogue/imports`, which takes a `source_uri` +
`supplier_id`, not individual product/asset payloads). This packet
therefore **does not** send app product rows into recommendation as
`Product`/`Asset` objects — there is no endpoint that accepts that shape.
What this packet actually does for the "product row → Product + Asset
refs" table row is the mapping in the other direction: take
recommendation's response (`BundleLineItem`: `product_id, category,
quantity, unit_price_minor_units, currency`, or a ranked candidate's
`product_id`), resolve it back to the app's own `products` row by ID/SKU,
and build the customer-facing view from that row — **never emitting
`tradePrice`** in the mapped result, per `products.tradePrice` in
`shared/schema.ts` and the adapter contract's explicit prohibition. Record
this bound explicitly in your completion evidence; do not implement a
speculative asset-upload call to recommendation, since none exists to call.

## Deliverables

1. `design-profile-mapper.ts`: `toDesignProfile(quizResponse: QuizResponse): DesignProfileIn | { needsInput: true; missingField: string }`.
   Maps `roomType → room_type`, `style → style`, `budgetRange → furniture_budget_minor_units`
   (convert the existing free-text bracket like `"$2K-$5K"` to a single
   integer minor-units figure using the **midpoint** of the range, in
   cents; if `budgetRange` does not parse against the app's known enum of
   ranges, return the `needsInput` shape naming `budgetRange` — do not
   guess a number), `keyFeatures → categories` (pass through as-is; empty
   array is itself a `needsInput` case naming `categories`, since
   `DesignProfileIn.categories` requires `min_length=1`). `atmosphere` and
   `currency` have **no source field anywhere in `quizResponses`** — always
   return the `needsInput` shape naming `atmosphere` unless/until a future
   packet adds that quiz field; `currency` defaults to `"USD"` **only**
   because every existing `products.price` in this app is already USD-only
   (confirm this against `shared/schema.ts`'s comments before relying on
   it, and if it is not confirmed, treat `currency` the same as
   `atmosphere` — `needsInput`).
2. `recommendation-client.ts`: `postRecommendations(profile: DesignProfileIn, catalogueSnapshotId: string): Promise<RecommendationResponseShape>` and `postBundle(...)` — thin `fetch` wrappers against `settings.recommendationUrl`, sending `schema_version: settings.contractVersion`. No retry/backoff logic (out of scope) — a non-2xx response is surfaced as a typed error carrying the response body's `code`/`message` (per `ai_services/contracts/v1/schemas/error.schema.json`'s `code, message, details, retryable, request_id` shape), never swallowed.
3. `product-response-mapper.ts`: `toAppProductRef(lineItem: BundleLineItemShape, appProduct: Product): AppProductRef` — asserts `appProduct.id === lineItem.product_id` (or throws a named error if the app has no matching product row) and returns a plain object with `sku, name, price, availability, images` from the app row, explicitly **omitting** `tradePrice` — the omission must be structural (the returned type has no `tradePrice` field), not just "don't read it".
4. `mapping.test.ts` — the named tests below, run via `npx tsx`.

## Named tests (in `mapping.test.ts`)

1. **Full mapping success is not claimed** — construct a `quizResponses`
   fixture row with `roomType="Living Room"`, `style="Midcentury Scandi"`,
   `budgetRange="$2K-$5K"`, `keyFeatures=["Comfortable Seat","Storage"]`;
   assert `toDesignProfile` returns the `needsInput` shape naming
   `atmosphere` (since no current quiz field supplies it) — this is the
   deliberately-incomplete-fixture case required by
   `ui_adapter_workflow.md` deliverable 5.
2. **Budget midpoint conversion**: `"$2K-$5K"` → `350000` (minor units,
   i.e. $3,500.00 midpoint) exactly; assert the integer, not a float.
3. **Empty categories rejected**: `keyFeatures=[]` → `needsInput` naming `categories`.
4. **Unparseable budget rejected**: `budgetRange="call for pricing"` → `needsInput` naming `budgetRange`, and the function does not throw.
5. **Product mapping omits trade price structurally**: construct an
   `appProduct` fixture with a non-null `tradePrice`; assert the returned
   `AppProductRef` object has no `tradePrice` key at all (`"tradePrice" in
   result === false`), not merely that it is `undefined`.
6. **Product mapping mismatch is rejected, not silently substituted**: a
   `lineItem.product_id` with no matching app product row throws a named
   error identifying the missing `product_id` — the function never
   fabricates a placeholder product.
7. **Client surfaces service error body verbatim**: mock `fetch` to return
   a 422 with a body matching `error.schema.json`'s required fields; assert
   `postRecommendations` rejects with an error object carrying the same
   `code` and `message`, not a generic "request failed".
